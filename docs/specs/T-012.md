# T-012 — iOS Auto-Start Feasibility Probe (NFC → Shortcuts → GPS)

Status: Proposed / Experimental (see D-028). This is a throwaway-quality-but-honest probe, NOT the BikeTrack app.
Do not touch `lib/` or `test/` of the main app. All work lives under `probes/ios_autostart/`.

## Goal
Prove on a real iPhone (free Apple ID + SideStore, no Mac) whether:
tap NFC tag → Shortcuts personal automation → BikeTrack "Start Ride" App Intent → GPS session starts →
first accepted fix is written to disk → real local notification → recording continues with screen locked in pocket.

## Hard constraints
- No Mac available. Swift cannot be compiled locally (Windows). The only compiler is Codemagic (macOS).
  Therefore: keep Swift small and conservative, avoid APIs you are not sure exist; cite the Apple doc URL in a
  comment above every non-trivial API use. If unsure an API exists on the target iOS, guard with `#available`.
- No paid capability: no Core NFC, no Associated Domains/Universal Links, no App Groups, no extensions (each extension
  costs an App ID; free limit is 10/week). No HealthKit in T-012A/B (separate gate later, T-012H).
- Bundle ID: `com.mohamedmtod.biketrack` (reuse later for the real app → keeps us inside SideStore's 3-app limit).
- Never report success for anything not executed. "App opened" ≠ "recording started". "Notification shown" ≠ "GPS continues".

## Part A — shell + build pipeline (no Swift logic)
1. `flutter create --org com.mohamedmtod --project-name biketrack_probe --platforms ios probes/ios_autostart`
   then set PRODUCT_BUNDLE_IDENTIFIER = `com.mohamedmtod.biketrack` and display name "BikeTrack Probe".
2. Info.plist (now, so Part B needs no plist churn):
   - `UIBackgroundModes` = [`location`]
   - `NSLocationWhenInUseUsageDescription`, `NSLocationAlwaysAndWhenInUseUsageDescription` (clear English text)
   - `CFBundleURLTypes` with scheme `biketrack` (fallback trigger `biketrack://start-ride`)
   - `UIFileSharingEnabled` = YES, `LSSupportsOpeningDocumentsInPlace` = YES (owner pulls the log via Files app)
3. Root `codemagic.yaml`, workflow `ios-probe-unsigned` (instance mac_mini_m2, max 30 min, manual trigger):
   - `cd probes/ios_autostart && flutter pub get && flutter build ios --release --no-codesign`
   - package: `cd build/ios/iphoneos && mkdir -p Payload && cp -R Runner.app Payload/ && zip -qry BikeTrackProbe.ipa Payload`
   - artifact: `probes/ios_autostart/build/ios/iphoneos/BikeTrackProbe.ipa`
   - also print `plutil -p Runner.app/Info.plist` into the log (proves plist keys survived).
4. Minimal Flutter UI: title, build number, and a text "Probe shell OK". Nothing else.
5. `docs/probes/T-012-runbook.md`: owner steps (Codemagic build → download IPA → SideStore install → open → refresh).

## Part B — native probe (Swift owns recording; Flutter only displays)
Files (one responsibility each) under `probes/ios_autostart/ios/Runner/Probe/`:
- `ProbeLog.swift` — append-only JSONL at `Documents/probe_log.jsonl`. Each line: `seq`, `wall_ms`, `uptime_ms`,
  `event`, payload. Write + `synchronize` per line (durability over speed). Never throws to callers.
- `RideRecorder.swift` — single owner of `CLLocationManager`. `start(trigger:)`, `stop()`.
  `allowsBackgroundLocationUpdates = true`, `pausesLocationUpdatesAutomatically = false`,
  `activityType = .fitness`, `desiredAccuracy = kCLLocationAccuracyBest`, `showsBackgroundLocationIndicator = true`.
  On iOS 17+: hold a `CLBackgroundActivitySession` while recording; on iOS 18+: also `CLServiceSession(authorization: .always)`
  if available (guard + doc URL). Persist `ride_active` + `ride_id` in UserDefaults; on app launch, if a ride was active,
  log `recovery_attempt` and restart updates.
  Accepted fix = horizontalAccuracy in (0, 50] m AND age <= 10 s. Log every fix: `fix_ts_ms`, `recv_ms`, `h_acc`,
  `speed`, `accepted`, `reject_reason`.
- `StartGate.swift` — after `start`: wait up to 20 s for first accepted fix that has been WRITTEN to the log.
  Success → post local notification "BikeTrack — Ride recording started" and log `notify_success`.
  Timeout/denied/error → post "BikeTrack — Couldn't start ride. Tap to start." (opens app) and log `notify_failure` with reason.
  Never post the success text on any failure path.
- `StartRideIntents.swift` — two App Intents (no extension; code in app bundle):
  - `StartRideForegroundIntent` ("Start Ride (open app)"): opens app (`openAppWhenRun = true`; if deployment target >= 26
    use `supportedModes` instead — check docs), then `RideRecorder.start(trigger:"intent_fg")`.
  - `StartRideBackgroundIntent` ("Start Ride (background)"): `openAppWhenRun = false`, `authenticationPolicy = .alwaysAllowed`,
    starts recording without UI. This is the experiment for the locked-phone case; it may fail — that is a valid result.
  - Both: `perform()` awaits StartGate result (<= 20 s) and returns a dialog "started" or throws a clear error.
    Log `intent_invoked` with variant, `UIApplication.applicationState`, `isProtectedDataAvailable`, auth status.
  - `AppShortcutsProvider` exposing both.
- `NotificationPermission.swift` — request alert+sound on first app open; log result.
- URL scheme handler `biketrack://start-ride` → `RideRecorder.start(trigger:"url")`.
- Lifecycle logging: launch (with launch options keys), foreground/background, willTerminate, memory warning.
- MethodChannel `biketrack/probe`: `status`, `start`, `stop`, `readLogTail(n)`, `clearLog`. Flutter screen: status, Start/Stop,
  permission buttons (When In Use → Always), last 30 log lines, Share log.

## Part C — log analyzer (testable on Windows)
`probes/ios_autostart/tool/analyze_log.dart` + tests in `probes/ios_autostart/test/`:
input JSONL → report: tap/intent → first accepted fix latency; count of gaps > 30 s by `fix_ts` and separately by `recv`;
accepted/rejected ratio; notify_success without prior accepted written fix (must be 0); recovery attempts.
Tests with fixtures for each metric, including malformed lines (skipped and counted, never crash).

## Owner test matrix (Gates)
G1 install/refresh · G2 in-app Start + 30-min pocket ride · G3 intent from Shortcuts manually (app open / app not running / locked)
· G4 NFC automation "Don't Ask" (unlocked / locked screen lit / screen off; fg vs bg intent) · G5 iOS-killed recovery
· G6 7-day refresh keeps intent + data. T-012H (later): HealthKit write under SideStore signing.

## Success criteria
- Unlocked phone: tag tap → first accepted fix <= 10 s, zero taps (target, measured under stated conditions).
- 30-min pocket ride: <= 1 gap > 30 s by fix_ts.
- `notify_success` never appears without a prior written accepted fix (analyzer = 0).
- Locked phone: record honestly which variant works; if none, fallback = failure notification → one tap.
