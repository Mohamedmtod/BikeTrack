| D-022 | ActivityClassifier is a pure function over a pre-aggregated ActivityWindow (cmTypes, cmConfidence?, cadenceSps?, speedMps? = median GPS speed of the window, stopPatternScore? in [0,1]). Hysteresis is a separate component (later task). | Section 7.6, testable on Windows | Accepted |
| D-023 | Invalid ActivityClassifier inputs: non-finite or negative speedMps/cadenceSps, and non-finite or out-of-range stopPatternScore, are treated as missing (term = 0). CM evidence counts only when cmTypes, after removing nothing, is exactly one of {cycling},{walking},{automotive},{stationary}, or exactly {automotive, stationary} (treated as automotive: car stopped at a light). Any other set (several types, running, unknown) gives CM term 0. ActivityClassifierConfig is validated by asserts: all weights and conf values >= 0; conf values <= 1; w1+w2+w3 <= 1; w1+w2+w5 <= 1; minBestScore and minMargin in [0,1]; cadenceFull > 0; each trapezoid a <= b <= c <= d. All scores are finite and in [0,1]. | T-008R: NaN propagation, unbounded config, ambiguous CM flags | Accepted |
| D-024 | ActivityStateMachine (§6.1) is a pure step(state, classifiedType, nowMs, cfg). The current type changes only after a candidate type persists for its hysteresis: cycling 30 s, walking 20 s, automotive 60 s, stationary 45 s, unknown 30 s, running 30 s. On switch, sinceMs = candidateSinceMs. Input equal to the current type clears the candidate. Input with nowMs <= lastUpdateMs is ignored (state unchanged). If nowMs - lastUpdateMs > maxEvidenceGapMs (120 s), the candidate restarts at nowMs. Initial type is unknown. A confidence field is deferred. | Prevent flicker; keep the real start time of a change | Accepted |
| D-025 | DomainConfig aggregates GpsFilterConfig, ActivityClassifierConfig, ActivityStateConfig and TripConfig. TripConfig holds §6.4 values: pendingMs 5 min, pauseMs 3 min, forgotMs 15 min, autoCloseMs 45 min, modeChangeMs 60 s, gapMs 30 s, pauseRegionRadiusM 100, cadenceWalkingMinSps 1.2. TripConfig.gapMs must equal GpsFilterConfig.gapMs (assert). | Single source for thresholds (D-014) | Accepted |
| D-026 | TripStateMachine phase 1: pure step(TripState, TripEvent, TripConfig) -> TripStepResult(state, commands). Statuses: pending, active, paused, completed; idle (no open trip) is TripState.status == null, TripStatus is not extended. Events: userStart, nfcScan, userStop, activity, tick. Events with nowMs < lastEventMs ignored. Deferred to phase 2 (M4): suspectedForgotten, autoClosed, needsReview, auto-detect start, GPS gap segments, reconcile. Pause does not close the segment. User stop while paused ends at pausedSinceMs. Start events with an open trip emit AskOpenTripDecision only. | §6.2 split; phase 1 needed for M2 | Accepted — amended by D-027, D-030 |
| D-027 | Amends D-026. | D-030 | Amends D-026 **only for its phase-2 deferred behavior**. (1) `GpsGapDetected(detectedAtMs, lastTrustedGpsMs)` requires both timestamps; close a known segment only at `lastTrustedGpsMs`, clamped within trip/segment bounds, then open `gap` at that safe boundary and emit `ResetGpsAnchor`; distance never crosses a gap. (2) `RecoveryDetected(detectedAtMs, lastTrustedGpsMs, lastKnownMovementMs?)` keeps its timestamps distinct: trusted GPS bounds only a known GPS segment; known movement only supplies a conservative potential trip end and never closes a known GPS segment. Recovery closes all open segments, represents unknown time as a gap where applicable, then ends the trip as `needsReview` with no open segment or open-trip state. (3) `TripState` gains nullable `TripCloseReason`; use `userStopped`, `autoClosed`, and `recoveredAfterGap`. `needsReview` is terminal review status; remove `TripStatus.autoClosed`. (4) Auto-start is allowed only from idle on a hysteresis-confirmed cycling `ActivityChanged`, uses its historical activity start, opens exactly one cycling segment, and stale/duplicate events cannot duplicate work. (5) From `paused`, qualifying inactivity reaches `suspectedForgotten`; cycling resumes active. At `autoCloseMs`, close at a monotonic conservative `lastKnownMovementMs`, transition to `needsReview` with close reason `autoClosed`, and emit `StopGps` then `EndTrip`. (6) Every derived timestamp is monotonic and clamped to trip/segment bounds; all thresholds remain in `TripConfig`. | Correct phase-2 representation, prevent GPS-gap distance bridging, and preserve reviewable conservative closures | Accepted |
| D-031 | Use Drift + SQLite for local persistence (§4, §5.2–§5.4). Schema v1 contains exactly `events`, `trips`, `segments`, `gps_points`, `activity_samples`, `bikes`, `config` and §5.3 indexes. `events` is the append-only source of truth: each event holds an integer UTC epoch-ms timestamp, EventSource, type, valid JSON payload text, nullable trip ID, and processed state. Payload and other raw fields are immutable after append; only `processed: false -> true` may change after application processing. T-015 provides production DB setup and an event repository only (no other repositories or live integration with Pigeon, RecorderBridge, iOS, UI, Riverpod, state machines, or ingestion). All timestamps come from callers, never generated by the repository. Future schema extensions require a new migration and approved decision. | Establish a testable local foundation without changing runtime ingestion or mutating raw evidence | Accepted |
| D-032 | T-016 preserves every RecorderBridge callback without deduplication, filtering, recalculation, retry, durable buffering, or acknowledgement. Raw GPS `events.tsUtc` is exactly `fixTsMs` (`CLLocation.timestamp` UTC epoch ms per D-029); `recvMs` stays separate in the payload; no uptime conversion or runtime time-base validation/replacement. Location-update lifecycle-equivalent, authorization, and location-error callbacks use an injectable application-layer clock. A failed `user_start` write prevents recorder start; a failed `user_stop` write never prevents recorder stop and is surfaced after attempting stop. Native callback write failures are surfaced in runtime/debug state without automatically stopping the recorder, retrying, or silently swallowing them. One in-memory serial async ingestion queue preserves callback arrival order as far as practical; failures do not block later callbacks and no in-memory deduplication occurs. T-016 implements only ingestion, recorder session, minimal debug UI, and relevant data/bridge/widget tests; no TripStateMachine processing, NFC/Core Motion, other repositories, or iOS/Pigeon contract changes. EventRepository adds only `readRecent(limit)` for processed and unprocessed events ordered by descending insertion ID, solely for the debug console. | Owner-approved raw evidence and manual recorder failure semantics for the M2 debug slice | Accepted |
| D-033 | Schema v2 makes unavailable native GPS fields (`altitude_m`, `v_accuracy_m`, `speed_mps`, `speed_accuracy_mps`, `course_deg`) nullable while preserving v1 data without inferred values. A versioned explicit-JSON singleton projection snapshot stores the insertion-ID cursor, complete `FilterState` and `TripState`, active trip/segment IDs, and pending manual attempt ID/timestamp. A processor handles one raw event per atomic SQLite transaction in `events.id` order: projection changes, `processed: false -> true`, and next snapshot/cursor commit together. One in-memory serial writer owns all manual and callback event appends in observed arrival order, with no dedupe/retry/buffer/ack/reordering. `user_start` is an intent; only matching persisted `recorder_start_confirmed` (after native `start` returns true) drives `UserStart`; a failed native start persists `recorder_start_failed`, and confirmation/failure persistence errors are visible at runtime. Open projected segments filter each raw location at `recvMs` and persist one accepted/rejected GPS row preserving nullable unavailable native values; without a segment, raw evidence only persists. Generated trip/segment IDs must remain stable across restart/retry. New trips/segments are user-classified at confidence 1.0 and have null/unknown distances; no totals, maps, routes, or derived distances are exposed. Only `user_start`, `recorder_start_confirmed`, `recorder_start_failed`, `user_stop`, and `location` affect projection; unknown events are observed then marked processed. `user_stop` affects an existing projected trip only and projection never invokes platform commands; `ResetGpsAnchor` only updates persisted filter state. | Owner-approved restart-safe M2 event projection behavior with conservative raw GPS preservation | Accepted |
| D-034 | After each successful raw-event append, schedule projection asynchronously without changing the completed persistence result or blocking native commands. One serialized single-flight drain calls `processNext()` until empty in stable SQLite insertion-ID order; concurrent and reentrant requests cannot race state. Drain pending events once after application/database initialization, including after restart. On the first projection failure, stop at the failing event, leave it and all later events unprocessed, and expose the blocking event ID, type, timestamp/payload details and error in observable runtime/debug state. Suppress automatic scheduling while blocked, while continuing raw appends and native actions; only an explicit debug retry or a fresh application startup clears the block and resumes draining. Preserve D-033 transactionality/idempotence. Debug UI shows each recent event's pending/processed state, drain state, blocking event/error and a Retry projections action that never invokes the native bridge. No NFC, Core Motion, maps, iOS/Swift, schema migration or domain-state-machine work. | Owner-approved automatic processing and safe failure isolation for M2 | Accepted |
